# Development records

Keep staged work plans, review findings, migration notes, validation checkpoints,
and recorded results here. Use a separate subdirectory for each work series.

- [Phase 0 cleanup](phase0/README.md): production baseline, LLVM version decision,
  test migration, backend findings, and hardware checkpoints.
- [Earlier feature and upstreaming plans](<history/Future Work.md>): historical
  proposals and implementation checklists.
- [Original backend working notes](<history/Notes and Thoughts.md>): the old
  development journal, retained as history rather than a current specification.

Instructions for using and contributing to the toolchain belong in the
[project README](../README.md), [reference documentation](../docs/), and
[test guides](../tests/README.md). Keep reusable commands and protocol descriptions
there; add dated run results and review decisions to this directory.

Large generated evidence archives remain under the ignored `build/` directory.
Their locations and checksums are recorded in the relevant checkpoint documents.
